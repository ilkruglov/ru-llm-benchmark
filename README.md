# RU LLM Benchmark — текст и компьютерное зрение

Сравнение больших языковых и vision-language моделей **на русском языке**, на прикладных
задачах российского бизнеса: бухгалтерия и налоги, юр. комплаенс, корпоративные финансы,
BI/данные, ВЭД и логистика, стройка, нефтегаз, промышленность, банки.

| | Задач | Моделей | Категорий |
|---|---:|---:|---:|
| **Текст** | 187 | 20 | 22 |
| **Компьютерное зрение (VL)** | 303 | 17 | 17 способностей × 8 отраслей |

Готовые отчёты (самодостаточные HTML — открываются онлайн через GitHub Pages):
* **[Текстовый бенчмарк](https://ilkruglov.github.io/ru-llm-benchmark/text-benchmark.html)** (или файл [`text-benchmark.html`](text-benchmark.html))
* **[VL-бенчмарк](https://ilkruglov.github.io/ru-llm-benchmark/vl-benchmark.html)** (или файл [`vl-benchmark.html`](vl-benchmark.html))

## Методология

**Параметры инференса — вендорские.** Для каждой модели берутся официально рекомендованные
temperature / top_p / top_k и способ включения reasoning (карточка модели или документация
провайдера), а не общие значения. Исключение: Qwen гоняется на temperature 0.6 вместо
рекомендованной 1.0 — на русском это заметно чище по языку без потери корректности.

**Судья — Claude Opus, единый метод для всех моделей.** Один агент на задачу видит эталон
(`notes_for_judge`) и ответы **всех** моделей сразу и выставляет каждой 4 критерия 0–10.
Ключевые решения:

* **Один прогон, один метод, один reasoning-эффорт** для всех участников. Смешивать методы
  судейства между моделями нельзя — это единственный способ получить сопоставимые баллы.
* **Покатегорийный фокус:** критерии корректности/формата конкретизируются под тип задачи
  (`judge-args-v3.json`), а не остаются общими.
* **Судится только видимый ответ** (`content`), reasoning-трейсы в пакет не кладутся — иначе
  модели с отдельным трейсом получали бы преимущество перед теми, у кого его нет.

**Итоговый балл** — взвешенная свёртка трёх критериев (reasoning в зачёт не идёт, т.к.
доступен не у всех моделей единообразно):

| | correctness | format | russian |
|---|---:|---:|---:|
| Текст | 0.6 | 0.1 | 0.3 |
| VL | 0.8 | 0.1 | 0.1 |

В VL русский и формат почти у потолка (85% оценок ≥9) и почти не различают модели —
основной сигнал даёт корректность распознавания. В тексте язык различает сильно, поэтому вес выше.

**Заголовочная метрика — macro** (среднее по категориям, каждая категория весит одинаково),
micro (среднее по задачам) показывается рядом.

## Честные оговорки

* **Контаминация.** Задачи и эталоны опубликованы. Со временем они попадут в обучающие
  выборки, и результаты на этом наборе перестанут быть валидными для новых моделей.
  Датируйте выводы.
* **Судья — тоже модель.** Opus систематически мягче/строже на отдельных типах задач.
  Абсолютные баллы менее надёжны, чем относительный порядок; разница <0.15 — шум.
* **Кибербез-фильтр.** Часть моделей семейства GPT (через codex CLI) не получает ответа
  на задачи об отказе от вредоносного кода — запрос режется платформенным фильтром
  провайдера до модели. Такие ячейки помечены `cyber_blocked` и **исключены** из подсчёта,
  а не засчитаны как провал: поведение модели там неизмеримо.
* **Одна выборка на задачу.** Прогон один, температура ненулевая → часть разброса
  (±0.1–0.2) — обычный шум сэмплинга.
* **VL-изображения не входят в репозиторий** (объём). В отчёте они есть как встроенные
  превью; для полного воспроизведения VL нужен исходный набор картинок.
* **Сырые ответы моделей не публикуются** — только задачи, эталоны, оценки судьи и отчёты.

## Воспроизведение

```bash
pip install requests pillow
cp .env.example .env && chmod 600 .env   # заполнить ключи

# 1. Инференс (resumable; повторный запуск добирает незавершённое)
python3 rerun_vendor.py text 8
python3 rerun_vendor.py vl 6

# 2. Модели, доступные только через codex CLI (GPT-5.5 / GPT-5.6)
CODEX_MODEL=gpt-5.6-sol python3 codex_model.py text medium 2
python3 merge_codex_contestants.py text gpt-5.6

# 3. Судейство — единый метод, все модели за один проход
python3 build_unified_judge.py text     # -> unified_judge_text_full.js
python3 build_unified_judge.py vl

# 4. Отчёты
python3 build_standalone.py text \
  --results master-benchmark-results-v3.json --scores-dir judging-scores-v4 \
  --out "Master Benchmark standalone.html" --tags "<список тегов>" \
  --title "Сравнение языковых моделей"
```

Шаг 3 генерирует workflow-скрипт, который запускает по одному судейскому агенту на задачу
(батчами, resumable). Оркестратор агентов не входит в репозиторий — подойдёт любой,
умеющий выполнить промпт и записать JSON по указанному пути.

## Структура

```
rerun_vendor.py            инференс по вендорским параметрам (HTTP, resumable, retry-on-empty)
codex_model.py             участники, доступные только через codex CLI
endpoints.py               реестр эндпоинтов (URL и ключи — из окружения)
neuraldeep.py              клиент провайдера с vision-поддержкой
build_unified_judge.py     единое судейство: пакеты + workflow-скрипт
merge_codex_contestants.py вливание ответов codex-моделей в общий набор
build_standalone.py        премиум-отчёт (hero, лидерборд, тепловая карта, разбор задач)
build_html_report_v2.py    рабочий текстовый отчёт (и общие утилиты)
build_vl_report.py         рабочий VL-отчёт (и превью изображений)
judging-scores-v4/         оценки судьи, текст (187 файлов)
vl-judging-scores-v4/      оценки судьи, VL (303 файла)
master-benchmark-tasks-v3.json   задачи + эталоны, текст
vl-ru-tasks.json                 задачи + эталоны, VL
```
